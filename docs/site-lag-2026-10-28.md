# Site lag hunt, 2026-10-28

Owen 2026-10-27 11:35 PM: "the whole site's a little laggy... no matter what [lobby] Bobby and I joined". Measured first,
fixed the biggest measured costs, measured again. 1 human + bots, headless Chrome at 240 Hz (Owen's display rate) from
Owen's PC to duelseries.com (ca-central-1), plus V8 profiles of the LIVE server process (inspector opened on loopback
with SIGUSR1, 75 s, closed again, no restart).

## Server (prod t3.micro, 2 vCPU, 1 GB, one Node process runs every game)

Ruled out by numbers: CPU (87% idle, steal avg 0.8%), memory (378 MB free, no swap use), disk wait 0.3%, nginx
(websocket config correct, 0 upstream timeouts; all 149 x 502 in 24 h were deploy restarts), transport (47 of 50
sessions on websocket, none stuck polling), GC (worst pause 32 ms in 13 min; local trace 5-7 ms mark-compacts).

What players feel: the event loop stalls 20-130 ms (rarely to 750 ms) in bursts, 8-34 per hour in active hours, which
freeze every game at once (snapshot gaps p95 45-68 ms, max 140-1577 ms in the browser). About half the late ticks
fall at seconds 0-2 of each wall-clock minute; nothing outside the app runs then (no cron, no outside traffic). The
live profile shows those seconds are the normal room work stacking up (agar.io grid rebuild, slither bots, snapshot
flushes) plus GC, so the cure is less base load on the one thread.

Bot counts follow the hour, so part of the drop is fewer bots (profiles at about 01:20, 02:10 and 03:00 EDT); the
rebuild and GameRoom rows are the fixes themselves.

Fixes: 1be7c8d (plain fixed snake rooms na_free, na_dollar, na_s0 stop simulating when only bots are left),
b88f4d0 (the old battle royale room sleeps while the event runs on the new engine), fbd6d8a (agar.io rebuilds its
spatial grid only when something moved; cells made or removed are applied at the next read in rebuild order).
Money: a room with an orphaned snake or a live human snake never pauses. agar.io equivalence: old and new sims side
by side on the production laws with 30 bot brains, splits and ejects, 3,000 steps, all 19,514 trace entries (every
bot view in order, every cell's id/x/y/size every step) identical; all 636 agar tests pass.

Left on the server: deploy churn (51 restarts in 24 h, each a disconnect plus a 4-minute stall burst); it ends when
the nightly building does.

## Games (live, direct page vs in the lobby frame)

Main-thread ms/s at 240 Hz before: Slither 457-619, agar 247-269, Paper 225-258, Pac-Man 248, Head Soccer 246-295,
Swim 163-180, Knockout 222, Rooftop 244-275, Crossy 224-244, Pool 231-264, Air Hockey 209. The lobby behind a game
frame adds only ~20 ms/s of paint. Long tasks were 0 in nearly every run.

The clip recorder (P saves the last 30 s; Slither, agar, Paper) was the biggest client cost: switching it off cut agar
247 -> 101 ms/s, Paper 262 -> 145, Slither in lobby 457 -> 328, and the GPU process by about half. Nearly all of it
is the encoder, which scales with pixels, so recording is capped at 1280x720 (was 1920x1080). Same-page A/B, extra
cost of recording over recording off, before -> after: busy 2D page main 71 -> 39 ms/s and GPU 227 -> 134; agar main
120 -> 80, GPU 337 -> 214; Paper main 73 -> 39, GPU 344 -> 202; Slither GPU 175 -> 149 (main too noisy to read).
Separate 60 s runs were dominated by game state (deaths, restarts) and did not settle it for Slither. Saved clips
checked in all three games (valid 720p H.264 MP4, AAC where the page had sound, the last 30 s; a 30 s Slither clip
23 MB -> 11 MB). 960x540 or 24 fps saved nothing more.

Awesome Tanks: the flagged health-bar width transition was dead CSS (removed); the live cash-out bar now fills with a
transform (ec06007).

Seen, not fixed: Knockout forces a layout every frame (paintClock, refit: 35-43 ms/s); Swim's DOM grows
(696 -> 12,988 nodes in one run) with 135 layouts/s; Crossy recalcs style every frame (placeTag); Slither draws
allocate 9-10 MB/s and the page runs 7 animation-frame loops.
